# 단계별 개발 과정

이 문서는 협업 시각화 아이디어가 재사용 가능한 로컬 프로그램이 되기까지의 과정과 결과를 정리합니다. 설계 중 제공된 참고 화면은 아이디어 참고에만 사용했으며 저장소에는 재배포하지 않습니다.

## 1단계 — 사무실 은유 정의

**목표:** 여러 AI의 작업을 한눈에 이해할 수 있게 만들기.

화면 규칙을 어두운 사무실 바닥, 프로젝트별 직사각형 방, 작은 직원 마커, 협업 테이블 네 가지로 단순화했습니다. 상태 가독성을 떨어뜨리는 장식적 3D·게임 요소는 제외했습니다.

**결과:** 프로젝트 필터, 프로젝트 방, 직원 상태, 협업 테이블, 최근 활동 패널을 갖춘 반응형 React 화면을 구현했습니다.

## 2단계 — 재현 가능한 데모 구현

**목표:** 시스템 연동 전에도 UI를 검토할 수 있게 만들기.

명시적인 데모 프로젝트와 이벤트를 추가했습니다. 라이브 API에 유효한 이벤트가 없을 때만 데모 모드가 나타나며 화면에서 분명하게 구분됩니다.

**결과:** 아래 이미지는 공개용 가상 데이터로 프로그램을 실제 실행해 캡처한 화면입니다.

![데모 모드 실행 화면](screenshots/dashboard-demo.png)

## 3단계 — 이벤트 파이프라인 연결

**목표:** Codex 생명주기 훅을 안정적인 화면 상태로 변환하기.

Python 수집기가 표준 입력의 JSON 이벤트 한 건을 받아 허용된 필드만 `~/.codex/ai-office/events.jsonl`에 추가합니다. Node 리듀서는 현재 파일과 회전 파일 한 개를 읽어 각 레코드를 검증하고 프로젝트, 직원, 활동 문구, 상태를 계산합니다.

**결과:** 메인 에이전트와 기능별 서브에이전트가 서로 다른 직원으로 같은 프로젝트 방에 나타납니다. 이벤트 파일은 20 MiB에서 한 번 회전합니다.

## 4단계 — 로컬 개인정보 경계 강화

**목표:** 프롬프트나 도구 작업을 감시 로그로 만들지 않고 필요한 상태만 표시하기.

수집기는 프롬프트, 명령, 도구 입출력, 파일 내용, 자격 증명, 전체 경로, 원본 식별자를 저장하지 않습니다. 리듀서는 두 번째 허용 목록을 적용하고 브라우저용 불투명 ID를 생성합니다. HTTP 서버는 `127.0.0.1`에만 바인딩됩니다.

**결과:** 테스트로 비공개 경로, 원본 직원·세션 ID, 프롬프트, 도구 데이터가 `/api/events`에 나오지 않음을 확인했습니다.

## 5단계 — 협업과 상태 신선도 모델링

**목표:** 함께 일하는 상황을 보여주고 오래된 정보를 현재 상태처럼 표시하지 않기.

같은 프로젝트에서 둘 이상의 직원이 작업·맥락 정리·종료 정리 중이면 협업 상태로 계산해 같은 테이블에 배치합니다. 마지막 이벤트 후 정확히 5분까지는 최신이며 그 이후에는 오래된 상태로 전환합니다.

프로젝트 방은 일반 활동 데이터가 바뀌는 동안 이전 위치를 유지합니다. 새 프로젝트는 기존 방을 움직이지 않고 뒤에 추가되며, 모든 메인 세션이 오프라인이 된 프로젝트만 활성 프로젝트 뒤로 이동합니다. 따라서 1.5초 폴링이 화면 블록의 반복 이동으로 이어지지 않습니다.

직원 이름은 허용된 역할과 도구 범주로만 계산하므로 프롬프트나 작업 기록을 읽지 않고도 `default` 같은 프레임워크 이름을 기능 담당 이름으로 바꿉니다. 완료된 서브에이전트와 종료된 메인 세션은 15초 동안 인계 상태를 표시한 뒤 방에서 퇴장하며 완료 이벤트는 최근 활동에 남습니다. 30분 동안 활동이 없는 직원도 유령 직원 정리 대상으로 숨기고 다음 이벤트가 오면 자동 복귀시킵니다. 명시적으로 완료된 직원은 재투입 이벤트가 있을 때만 같은 직원이 방에 다시 나타납니다.

활동 패널은 지시, 배정, 인계, 승인, 맥락 정리, 세션 전환을 독립 이벤트로 유지합니다. 반복되는 도구 시작·완료 이벤트는 직원과 안전한 업무 범주별로 묶고 10분 동안 새 활동이 없을 때 다음 흐름으로 나눕니다. 각 카드는 코드 변경, 화면 검증, 자료 조사, 협업 조율, 품질 검증, 명령 실행·상태 점검 같은 범주와 활동 시간, 세부 단계 수를 보여줍니다. 프롬프트, 명령, 파일 경로, 도구 입력과 출력은 설명 생성에 사용하지 않습니다.

세션·지시·종료 이벤트만 있는 기록은 단순 채팅으로 보고, 도구·서브에이전트·승인 이벤트로 Codex 작업이 확인될 때만 프로젝트를 표시합니다. 마지막 활동 후 24시간이 지나면 프로젝트를 숨기고 다음 작업 이벤트가 오면 자동 복귀시킵니다. 우측 패널의 프로젝트 선택은 사무실 맵 선택과 분리해 한 프로젝트의 기록을 살펴봐도 사무실 표시 범위는 바뀌지 않습니다.

구체적인 내용은 로컬 선택 기능입니다. 켠 경우에도 짧게 마스킹한 사용자 지시와 허용된 협업 도구의 `message` 필드만 저장하고 API에서 다시 마스킹합니다. 서브에이전트 둘 이상이 협업할 때만 회의 테이블에 최근 논의를 표시합니다. 셸·패치 입력, 일반 도구 입출력, transcript, 서브에이전트 최종 메시지는 계속 제외합니다.

**결과:** 협업, CEO 승인 대기, 작업 종료 전환, 연결 끊김, 상태 오래됨을 서로 구분해 표시합니다.

![개인정보를 제거한 라이브 모드 실행 화면](screenshots/dashboard-live-sanitized.png)

## 6단계 — Windows 로그인 시 숨김 실행

**목표:** 터미널 창 없이 대시보드를 계속 사용할 수 있게 만들기.

설치 스크립트가 앱을 빌드·검증하고 이벤트 수집기와 훅을 설치한 뒤 현재 사용자의 시작프로그램 바로가기를 만듭니다. VBScript 실행기는 저장소 위치를 동적으로 찾고, 같은 Node 서버의 중복 실행을 피하며, 창을 숨기고 서버가 비정상 종료되면 다시 시작합니다.

**결과:** Windows 로그인 후 자동 실행되며 문제가 있을 때 `npm run start:office`로 직접 진단할 수 있습니다.

## 7단계 — 비공개 원격 열람

**목표:** 공개 인터넷에 노출하지 않고 본인의 다른 기기에서 상태 확인하기.

Tailscale Serve로 localhost 서버를 Tailnet 내부에만 프록시할 수 있게 했습니다. Funnel은 사용하지 않습니다. 정적 호스팅은 사용자 PC의 이벤트 파일을 읽을 수 없으므로 데모 전용으로 구분했습니다.

**결과:** 로컬 라이브 모드와 선택적 비공개 원격 모드의 보안 경계가 분명해졌고, 개인 Tailnet 주소는 저장소에 포함하지 않았습니다.

## 8단계 — 공개 재사용 패키징

**목표:** 다른 사용자가 복제, 이해, 설치, 검증, 제거할 수 있게 만들기.

영문·한글 문서, MIT 라이선스, 저장소 구조, 보안 문서, 아키텍처, Windows 설치·제거 스크립트, 단계별 개발 기록, 실제 실행 화면, 로컬 데이터 제외 규칙을 추가했습니다.

## 현재 한계

- UI는 한국어 중심이고 저장소 문서는 한·영으로 제공합니다.
- 프로젝트 폴더명과 에이전트 역할명은 표시 정보로 화면에 나타납니다.
- Codex 훅 신뢰는 사용자가 직접 검토해야 합니다.
- 자동 설치는 Windows 대상입니다. Node 전면 실행은 이식 가능하지만 macOS/Linux 백그라운드 시작 스크립트는 아직 없습니다.
- 정적 호스팅은 쇼케이스이며 실시간 원격 대시보드가 아닙니다.
- 현재 훅에는 ChatGPT와 Codex 제품 출처를 직접 구분하는 필드가 없습니다. 따라서 실제 도구·서브에이전트·승인 작업을 기준으로 분류하며, 도구를 전혀 쓰지 않는 텍스트 전용 Codex 작업도 단순 채팅과 함께 의도적으로 숨겨집니다.
